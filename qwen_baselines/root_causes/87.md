**Fix type**

**Where to apply it** *(file:line range)*:

`Main.main`. The old source is on a single line, so line ranges are not meaningful. `ImproveList` needs no change for the fix; the supplied fixed version only drops the unused `java.util.concurrent` import.

**Description of the fix:**

Replace the fixed thread pool and its two `execute(...)` calls with two `Thread`s that reuse the existing lambdas, start them, and `join()` both. Remove `shutdown()`, `awaitTermination(...)` and the unused import.

**Code sketch**

```java
// before

ExecutorService es = Executors.newFixedThreadPool(2);
es.execute(() -> { list.add(1); });
es.execute(() -> { list.putIfAbsent(1); });
es.shutdown();
es.awaitTermination(1, TimeUnit.SECONDS);
```

```java
// after

Thread t1 = new Thread(() -> { list.add(1); });
Thread t2 = new Thread(() -> { list.putIfAbsent(1); });
t1.start();
t2.start();
t1.join();
t2.join();
```

**Why it removes the symptom:**

n/a as an interleaving fix. The new program uses only `Thread`, `synchronized` and `join`, so the state space JPF has to explore is small and the search can finish.

**Validation:**

The supplied fixed version (executor → plain threads, lambdas kept) is taken as passing JPF per the case record. This was not re-run here.

**Behavioral note:**

The old code waited at most 1 second and ignored the result of `awaitTermination`. The new code waits for both threads to finish. This does not affect the correctness of the logic.
